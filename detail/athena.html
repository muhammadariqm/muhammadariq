2.1

Heap Smash v1

PWN
Deskripsi

Challenge kategori PWN yang berfokus pada eksploitasi heap. Saat aplikasi dijalankan, flag dimuat ke dalam heap kemudian langsung dibebaskan (free). Walaupun pointer telah dilepas, isi memori masih tersimpan sehingga memungkinkan peserta memperoleh kembali data tersebut apabila blok heap dialokasikan ulang.

Tujuan

Memperoleh flag dengan memanfaatkan perilaku allocator pada heap yang mengembalikan blok memori tanpa menghapus isi sebelumnya.

Metode Penyelesaian
  1. Menghubungkan client ke server challenge menggunakan Netcat pada port 1337.
  2. Melakukan alokasi note baru menggunakan perintah A.
  3. Memilih ukuran alokasi yang sesuai sehingga allocator menggunakan kembali blok heap sebelumnya.
  4. Tidak melakukan penulisan data baru agar isi memori lama tidak tertimpa.
  5. Membaca isi note menggunakan perintah R.
  6. Flag yang masih tersimpan pada heap berhasil ditampilkan.
Hasil
$ nc target.athena2026.ctf 1337
$ A → alokasi note baru (reuse blok heap lama)
$ R → baca isi note tanpa overwrite
Challenge berhasil diselesaikan melalui heap reuse / uninitialized heap memory.
2.2

Net MITM TLS

INFRA
Deskripsi

Challenge ini menguji kemampuan peserta dalam melakukan Man-in-the-Middle (MITM) terhadap komunikasi TLS. Sebuah service secara berkala mengirimkan flag ke server menggunakan protokol HTTPS. Peserta diminta membuat server TLS palsu dengan sertifikat yang sesuai sehingga koneksi korban dapat diarahkan menuju server tersebut.

Tujuan

Mengintersepsi komunikasi TLS dan memperoleh flag yang dikirimkan oleh service.

Metode Penyelesaian
  1. Menghubungkan ke shell challenge.
  2. Membuat Certificate Authority (CA) lokal.
  3. Membuat sertifikat TLS dengan Common Name sesuai domain target.
  4. Menjalankan HTTPS server pada port yang ditentukan.
  5. Mengarahkan koneksi service menuju server palsu.
  6. Menunggu hingga request yang berisi flag diterima.
Hasil
$ openssl req -x509 -new -nodes -out ca.pem
$ https-server --cert local.pem --port 443
Flag berhasil diperoleh dari request HTTPS yang berhasil diintersepsi.
2.3

Tiny ECC Tweak

CRYPTO
Deskripsi

Challenge ini menggunakan algoritma Elliptic Curve Cryptography (ECC). Peserta diberikan dua buah signature beserta ciphertext. Kerentanan terdapat pada proses pembangkitan bilangan acak (nonce) sehingga memungkinkan private key dihitung kembali.

Tujuan

Mengembalikan private key dan mendekripsi ciphertext untuk memperoleh flag.

Metode Penyelesaian
  1. Menganalisis file pub.txt.
  2. Membandingkan kedua signature ECC.
  3. Mengidentifikasi kelemahan pada penggunaan nonce.
  4. Menghitung private key menggunakan persamaan ECC.
  5. Mendekripsi ciphertext menggunakan private key yang berhasil diperoleh.
Hasil
$ compare(sig_1, sig_2) → nonce reuse terdeteksi
$ solve_private_key(r, s1, s2, z1, z2)
Private key berhasil direkonstruksi, ciphertext berhasil didekripsi menjadi flag.
2.4

Triplet Tweak

CRYPTO
Deskripsi

Challenge ini menyajikan tiga buah ciphertext yang berasal dari pesan yang sama namun menggunakan parameter berbeda. Peserta diminta menemukan hubungan matematis antar ciphertext sehingga plaintext dapat dipulihkan.

Tujuan

Mendapatkan plaintext asli melalui analisis kriptografi.

Metode Penyelesaian
  1. Mengumpulkan ketiga ciphertext.
  2. Menganalisis hubungan antar parameter enkripsi.
  3. Menggunakan teknik kriptanalisis yang sesuai.
  4. Menghitung kembali plaintext.
  5. Memverifikasi hasil dekripsi.
Hasil
$ analyze(ct1, ct2, ct3) → relasi parameter ditemukan
$ recover_plaintext()
Plaintext berhasil dipulihkan sehingga flag dapat diperoleh.
2.5

Upload Lantern

INFRA
Deskripsi

Challenge ini menyediakan fitur upload file beserta endpoint preview. Kerentanan terdapat pada proses validasi nama file sehingga memungkinkan akses terhadap file yang seharusnya tidak dapat diakses.

Tujuan

Mengakses file yang berisi flag melalui kelemahan pada fitur upload.

Metode Penyelesaian
  1. Menguji fungsi upload file.
  2. Mengamati request menggunakan Burp Suite.
  3. Mengidentifikasi kelemahan sanitasi nama file.
  4. Melakukan manipulasi parameter endpoint preview.
  5. Mengakses file target yang berisi flag.
Hasil
$ POST /upload → filename tidak tersanitasi dengan aman
$ GET /preview?file=... → akses ke file target
Flag berhasil diperoleh melalui eksploitasi endpoint preview.
2.6

Net Custom Protocol

INFRA
Deskripsi

Challenge ini menggunakan protokol TCP kustom dengan format ECHO|k|data. Peserta diminta melakukan reverse engineering terhadap format komunikasi tersebut untuk memperoleh secret.

Tujuan

Mendapatkan secret dengan memahami struktur protokol jaringan.

Metode Penyelesaian
  1. Menghubungkan ke service menggunakan Netcat.
  2. Mengirim beberapa payload percobaan.
  3. Menganalisis format request dan response.
  4. Menentukan struktur protokol.
  5. Membuat payload yang mampu menampilkan secret.
Hasil
$ nc target.athena2026.ctf 4444
$ → ECHO|k|data (format protokol teridentifikasi)
Secret berhasil diperoleh setelah format protokol berhasil dipahami.
2.7

Table Stakes

REV
Deskripsi

Challenge ini berupa executable yang hanya melakukan proses validasi flag. Program tidak pernah menampilkan flag sehingga peserta harus melakukan reverse engineering terhadap binary tersebut.

Tujuan

Merekonstruksi flag melalui analisis kode program.

Metode Penyelesaian
  1. Membuka binary menggunakan Ghidra atau IDA Free.
  2. Mengidentifikasi fungsi utama yang melakukan validasi.
  3. Menganalisis proses perbandingan input dengan data internal.
  4. Mereverse algoritma validasi.
  5. Menyusun flag berdasarkan hasil analisis.
Hasil
$ ghidra ./table_stakes → decompile main()
$ reverse(check_flag) → algoritma validasi ditemukan
Flag berhasil direkonstruksi tanpa melakukan brute force.

Kesimpulan

Seluruh challenge pada CTF Athena 2026 memberikan pengalaman dalam berbagai bidang keamanan siber, mulai dari eksploitasi heap (PWN), keamanan infrastruktur (INFRA), kriptografi (CRYPTO), hingga reverse engineering (REV). Setiap challenge menuntut pendekatan yang berbeda, seperti analisis memori, manipulasi protokol jaringan, pemecahan algoritma kriptografi, dan analisis binary. Melalui penyelesaian challenge tersebut, kemampuan analisis, pemecahan masalah, serta pemahaman terhadap konsep keamanan informasi dapat ditingkatkan secara praktis. Dokumentasi ini juga menjadi referensi mengenai metodologi penyelesaian challenge yang sistematis dan dapat digunakan sebagai bahan evaluasi maupun pembelajaran di masa mendatang.
