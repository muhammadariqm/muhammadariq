01

Ringkasan Alur

OVERVIEW

Setiap git push ke branch main repository muhammadariqm/CMS memicu GitHub Actions. Job dijalankan oleh self-hosted runner yang terpasang langsung di STB, lalu memanggil script deploy lokal. Tidak ada port SSH yang dibuka ke internet.

  1. Push ke main (atau jalankan manual lewat workflow_dispatch).
  2. GitHub mengirim job ke runner stb-hg680p melalui koneksi keluar dari STB.
  3. Runner melakukan checkout kode, lalu menjalankan sudo -n /usr/local/sbin/deploy-cms.
  4. Script menyalin kode ke folder website live tanpa --delete.
  5. Workflow memeriksa http://127.0.0.1:8081; harus mengembalikan HTTP 200.

02

Memilih Metode Deploy

DESAIN

GitHub Actions berjalan di cloud, sedangkan 192.168.1.100 adalah IP lokal rumah. Runner cloud tidak bisa menjangkaunya secara langsung.

Opsi Kelebihan Kekurangan / hasil
SSH dari GitHub ke STB Sederhana secara konsep Perlu membuka SSH ke internet atau mengatur jalur tambahan
SSH lewat Cloudflare Tunnel Tanpa port terbuka Tunnel yang ada adalah Quick Tunnel ke http://cms-laravel:80; hanya HTTP, bukan SSH
Self-hosted runner di STB Hanya koneksi keluar; perintah Docker/file berjalan lokal; tunnel website tidak diubah Dipilih. Runner harus dibatasi ke repository sendiri
Catatan: Sempat disiapkan SSH key stb_deploy (ed25519) di laptop dan dipasang ke STB. Key itu tidak dipakai oleh metode runner; hapus barisnya dari ~/.ssh/authorized_keys di STB bila tidak diperlukan lagi.
03

Persiapan Repository di STB

GIT

Folder website live harus dicek sebelum deploy. Jangan menjalankan git clone atau menghapus folder, karena folder ini dipakai container Laravel. 

cd /srv/data/websites/CMS
git status
git remote -v
git branch --show-current

Hasil yang tercatat: branch main, tetapi working tree punya perubahan dan banyak file untracked (folder konten seperti articles/, banners/, gallery/, projects/, settings/, file .env.backup-*, backup container, dan konfigurasi Docker).

Jangan jalankan git pull, git reset --hard, atau git clean di folder live. Perintah itu bisa menimpa atau menghapus perubahan lokal dan konten yang dikelola lewat CMS. Karena itu deploy memakai checkout terpisah di runner, lalu menyalin file kode saja.
04

Memasang Runner

RUNNER

Kendala: microSD berformat VFAT

Ekstrak runner di /srv/data menghasilkan error Cannot change ownership to uid 1001. Penyebabnya, microSD terpasang sebagai vfat yang tidak mendukung ownership dan permission Linux. 

findmnt -T /srv/data -o TARGET,SOURCE,FSTYPE,OPTIONS
df -h /srv/data /
Lokasi Filesystem Ruang kosong Keputusan
/srv/data (microSD) vfat ± 20 GB Tidak cocok untuk runner
/ (eMMC) ext4 1,9 GB → 1,3 GB setelah salin Dipakai; runner 592 MB

Salin ke ext4 dan beri akses ke fnet1

pgrep -af 'Runner.Listener|Runner.Worker'
mkdir -p /opt/actions-runner
cp -a /srv/data/github-runner/actions-runner/. /opt/actions-runner/
chown -R fnet1:fnet1 /opt/actions-runner

config.sh menolak berjalan sebagai root (Must not run with sudo), jadi runner dijalankan oleh user biasa fnet1.

Registrasi runner

runuser -u fnet1 -- bash -c 'cd /opt/actions-runner && ./config.sh --unattended --url https://github.com/muhammadariqm/CMS --token TOKEN_DARI_GITHUB --name stb-hg680p --labels self-hosted,Linux,ARM64,stb-hg680p'
TOKEN_DARI_GITHUB adalah placeholder. Ambil token baru dari Settings → Actions → Runners → New self-hosted runner. Token bersifat sementara; jangan di-commit atau dikirim ke chat.

Jalankan sebagai service

cd /opt/actions-runner
./svc.sh install fnet1
./svc.sh start
./svc.sh status
Status active (running), log menampilkan Connected to GitHub dan Listening for Jobs. Service enabled, sehingga aktif otomatis setelah STB restart.
Catatan: Folder runner lama di microSD (/srv/data/github-runner) dibiarkan sebagai cadangan.
05

Script Deploy dan Izin sudo

DEPLOY

Runner berjalan sebagai fnet1, sedangkan folder live butuh hak lebih tinggi. Solusinya satu script khusus yang boleh dipanggil lewat sudo tanpa password, bukan memberi fnet1 akses root penuh.

  • Script: /usr/local/sbin/deploy-cms (menyalin kode ke folder live tanpa --delete).
  • Aturan sudoers: /etc/sudoers.d/deploy-cms, hanya untuk script tersebut.
  • Script menolak berjalan bila checkout /opt/actions-runner/_work/CMS/CMS/ belum ada. 
sudo visudo -cf /etc/sudoers.d/deploy-cms
sudo -u fnet1 sudo -n /usr/local/sbin/deploy-cms

Hasil uji: parsed OK, lalu pesan ERROR: checkout CMS belum ditemukan. Itu hasil yang diharapkan karena izin sudo bekerja dan script menolak berjalan tanpa checkout.

Catatan: Isi lengkap script dan aturan sudoers tidak ikut tercatat di catatan ini. Salin dari server bila ingin mendokumentasikannya, dan pastikan tidak ada rahasia di dalamnya.
06

Workflow GitHub Actions

YAML

Dua workflow lama (docker-ci.yml dan deploy.yml versi lama) dihapus dan diganti satu file: 

# .github/workflows/deploy.yml
name: Deploy CMS to STB

on:
  push:
    branches:
      - main
  workflow_dispatch:

permissions:
  contents: read

concurrency:
  group: cms-stb-deployment
  cancel-in-progress: false

jobs:
  deploy:
    name: Deploy on STB HG680P
    runs-on: [self-hosted, Linux, ARM64, stb-hg680p]

    steps:
      - name: Checkout latest code
        uses: actions/checkout@v4

      - name: Deploy CMS files
        run: sudo -n /usr/local/sbin/deploy-cms

      - name: Check website
        run: |
          set -e
          HTTP_CODE=$(curl -sS -o /dev/null -w '%{http_code}' http://127.0.0.1:8081)
          echo "CMS HTTP status: ${HTTP_CODE}"
          if [ "$HTTP_CODE" != "200" ]; then
            echo "CMS health check failed."
            exit 1
          fi
  • concurrency memastikan dua deploy tidak berjalan bersamaan.
  • permissions: contents: read membatasi hak token workflow.
  • Tidak ada migration, seeder, atau restart container di workflow ini.
  • Tanpa --delete, file yang sudah dihapus dari GitHub bisa tertinggal di folder live. Ini disengaja untuk deploy awal.
07

Verifikasi

CEK

Run pertama workflow Deploy CMS to STB berstatus Success: job di STB 27 detik, total 34 detik, dipicu push ke main. Cek manual dari STB: 

curl -sS -o /dev/null -w 'HTTP %{http_code}\n' http://127.0.0.1:8081
systemctl status 'actions.runner.*' --no-pager
docker ps
Hasil tercatat: HTTP 200. Runner active, website tetap merespons setelah deploy.
Catatan: Run sukses belum membuktikan perubahan kode tampil di website. Uji dengan perubahan teks kecil pada halaman publik, push, lalu cek apakah workflow jalan otomatis, teks berubah, dan folder media serta konfigurasi tetap utuh. Warning Node.js 20 deprecated pada actions/checkout@v4 bukan kegagalan; naikkan versinya nanti.
08

Keamanan

SECURITY
  • Self-hosted runner menjalankan perintah langsung di STB. Pakai hanya untuk repository pribadi; jangan aktifkan untuk fork atau pull request dari orang lain.
  • Jangan simpan token registrasi runner, private key, atau isi .env di repository dan dokumentasi.
  • Runner berjalan sebagai fnet1, bukan root; hak root hanya lewat satu script di sudoers.
  • Pastikan .env, .env.backup-*, container-backup.json, dan file backup lain masuk .gitignore dan tidak ikut ter-commit.
  • Port SSH 22 tidak perlu dibuka ke internet untuk alur ini.
Private key stb_deploy yang pernah dibuat jangan dibagikan. Bila sudah tidak dipakai, hapus file key dan public key-nya dari STB maupun laptop.
