1. Pendahuluan

Security Configuration Assessment (SCA) merupakan salah satu modul fundamental pada platform Wazuh yang digunakan untuk mengevaluasi dan memverifikasi konfigurasi keamanan sistem operasi dan aplikasi berdasarkan standar keamanan internasional yang diakui secara global seperti CIS (Center for Internet Security) Benchmarks.

Melalui SCA, administrator sistem dapat secara proaktif mengidentifikasi celah keamanan (misconfigured settings), hak istimewa berlebih yang tidak aman, atau kebijakan akses yang lemah pada host target, sehingga langkah-langkah perbaikan (remediation) dapat segera dilakukan untuk memperkecil *attack surface*.

2. Tujuan Implementasi

Implementasi modul Security Configuration Assessment ini dirancang untuk mencapai beberapa objektif keamanan utama di bawah ini:

  • Menilai Kepatuhan: Menganalisis tingkat kepatuhan konfigurasi keamanan sistem operasi host secara berkala.
  • Deteksi Deviasi: Mengidentifikasi kebijakan konfigurasi sistem lokal yang tidak sesuai atau melanggar aturan standar CIS Benchmark.
  • Panduan Remediasi: Menyediakan rekomendasi teknis perbaikan yang presisi untuk setiap konfigurasi kebijakan keamanan yang berstatus Failed (Gagal).
  • Verifikasi Otomatis: Memvalidasi hasil perbaikan (remediation) secara real-time melalui proses pemindaian ulang otomatis setelah konfigurasi diterapkan.

4. Langkah Konfigurasi — Aktivasi Modul

Secara default, modul SCA telah terpasang dan aktif saat instalasi Wazuh Agent selesai dilakukan. Pemindaian otomatis berjalan berdasarkan file policy CIS yang sesuai dengan versi sistem operasi target. Blok konfigurasi di bawah ini dideklarasikan pada file ossec.conf milik agent: 

<sca>
  <enabled>yes</enabled>
  <scan_on_start>yes</scan_on_start>
  <interval>12h</interval>
  <skip_nfs>yes</skip_nfs>
</sca>

5. Pengujian — Aturan CIS Benchmark

Untuk memvalidasi cara kerja sistem, dilakukan pengujian audit kebijakan keamanan akun lokal menggunakan parameter aturan CIS berikut:

  • Rule ID: 26000
  • Deskripsi Aturan: Ensure 'Enforce password history' is set to '24 or more password(s)'.
  • Kondisi Awal: Status terdeteksi Failed
  • Penyebab: Nilai penyimpanan riwayat password (Password History) pada sistem Windows target saat ini masih bernilai 0 (Disabled).
Buka Screenshot Detail Rule Failed (SCA-2)

6. Remediation — Perbaikan Konfigurasi

Guna menyelaraskan sistem dengan standar CIS Benchmark, jalankan shell Command Prompt (cmd.exe) dengan hak akses Administrator di endpoint Windows, kemudian eksekusi perintah perbaikan berikut: 

net accounts /uniquepw:24
net accounts /minpwage:1
net accounts /minpwlen:14
net accounts /lockoutthreshold:5
Buka Screenshot CMD Sebelum Remediation (SCA-3)

Lakukan verifikasi lokal hasil konfigurasi baru dengan perintah: 

net accounts

Output verifikasi yang berhasil di dalam konsol terminal:

7. Hasil Pengujian — Validasi Dashboard

Setelah perbaikan konfigurasi diterapkan di sisi sistem operasi Windows, modul SCA akan otomatis memindai ulang host pada jadwal berikutnya (atau dipicu secara manual lewat restart service).

Status pemeriksaan untuk Rule ID 26000 kini telah berubah menjadi Passed (Lolos/Sukses) di dashboard monitoring.

8. Analisis Hasil Audit

Pemantauan yang dilakukan membuktikan bahwa modul SCA Wazuh bekerja secara akurat dan sangat responsif terhadap perubahan kebijakan konfigurasi keamanan yang diterapkan pada host.

Mekanisme audit terintegrasi ini tidak hanya mengidentifikasi kerentanan secara statis, namun secara dinamis memperbarui status kepatuhan berdasarkan kondisi nyata di endpoint tanpa membutuhkan intervensi manual yang rumit dari sisi operator keamanan. Hal ini mendukung siklus deteksi, perbaikan (*remediation*), dan pelaporan kepatuhan secara berkelanjutan (*Continuous Compliance*).

Kesimpulan

Implementasi modul Security Configuration Assessment (SCA) pada Windows 11 menggunakan Wazuh SIEM berhasil dilakukan dengan stabilitas tinggi. Sistem ini terbukti mampu memantau, mendeteksi penyimpangan (deviations) kebijakan CIS Benchmark, memberikan instruksi langkah remediation yang jelas, hingga memverifikasi kembali keberhasilan implementasi kontrol keamanan tersebut secara otomatis.
