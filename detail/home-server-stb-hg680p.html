02

Perangkat dan Jaringan

JARINGAN
  • Perangkat utama: STB HG680P.
  • Sistem operasi: Armbian Linux, kernel berbasis Linux.
  • Arsitektur: ARM64 / aarch64.
  • Penyimpanan tambahan: microSD 32 GB, dipasang di /srv/data.
  • Koneksi jaringan: kabel LAN ke router.
  • Alamat IP lokal yang tercatat: 192.168.1.100.
  • Router yang tercatat: 192.168.1.1.
  • IP laptop yang pernah terlihat: 192.168.1.138.
Alamat IP bisa berubah jika router menggunakan DHCP. Jika SSH tidak tersambung, cek daftar perangkat pada router atau periksa alamat IP STB dari terminalnya. Jangan langsung mengubah konfigurasi jaringan tanpa mengetahui IP terbaru.
03

Penyimpanan dan Folder

STORAGE

microSD dipasang pada /srv/data. Struktur folder yang direncanakan/digunakan untuk memisahkan data server antara lain: 

/srv/data/
├── backups/
├── docker/
├── hermes/
├── websites/
│   └── pertama/
│       └── index.html
└── CMS-persistent/
    └── storage/

Website statis pertama disimpan di /srv/data/websites/pertama/. Backup storage CMS pernah disalin ke /srv/data/CMS-persistent/storage/.

Mount microSD pernah terlihat sebagai /dev/mmcblk1p1 dengan filesystem VFAT. Sistem operasi berada pada eMMC, dengan root filesystem di partisi ext4. Detail partisi dapat berubah jika instalasi diulang.

Periksa mount dan ruang kosong

lsblk -f
df -h
findmnt /srv/data
cat /etc/fstab
Sebelum mengedit /etc/fstab, pastikan UUID/partisi yang benar dan buat salinan file. Salah konfigurasi dapat membuat penyimpanan tidak ter-mount setelah reboot.
04

Masuk ke Server melalui SSH

SSH

Dari PowerShell Windows, jalankan:

ssh root@192.168.1.100

Jika IP berubah, ganti alamat tersebut dengan IP STB yang terbaru. Saat pertama kali tersambung, SSH mungkin meminta konfirmasi fingerprint host.

Setelah masuk, perintah-perintah di bawah dijalankan di terminal STB, bukan di PowerShell laptop, kecuali jika disebutkan sebaliknya.

05

Docker dan Container

DOCKER

Docker digunakan untuk memisahkan layanan sehingga website, database, dan tunnel dapat dikelola secara terpisah.

Perintah dasar

docker --version
docker compose version
systemctl is-active docker
docker ps
docker ps -a
docker images
docker stats --no-stream

docker ps menampilkan container yang sedang berjalan. docker ps -a juga menampilkan container yang sudah berhenti.

Inventaris container yang pernah tercatat

Nama container Fungsi Port host Catatan
website-pertama Nginx untuk website statis 8080 → 80 Konten di-mount read-only dari /srv/data/websites/pertama.
cms-laravel Aplikasi Laravel dengan Apache 8081 → 80 Pernah terdeteksi tanpa Docker volume/bind mount.
mariadb-news Database MariaDB 3307 → 3306 Data pernah di-bind ke /mnt/mariadb-data/data.
cloudflare-cms Cloudflare Tunnel untuk CMS Tidak ada port web host yang perlu dibuka Berbagi network Docker cms-network dengan CMS.

Port dan status di tabel merupakan catatan historis. Verifikasi lagi dengan docker ps sebelum digunakan.

06

Website Statis dengan Nginx

WEB

Website percobaan pertama disimpan di:

/srv/data/websites/pertama/index.html

Konten halaman menggunakan judul “Server Rumah Ariq” dan menjelaskan bahwa website di-host menggunakan Armbian, Docker, dan Nginx.

Container Nginx pernah dibuat dengan perintah berikut:

docker run -d \
  --name website-pertama \
  --restart unless-stopped \
  -p 8080:80 \
  -v /srv/data/websites/pertama:/usr/share/nginx/html:ro \
  nginx:alpine

Jika container sudah ada, jangan jalankan perintah pembuatan ulang secara membabi buta karena nama container akan bentrok. Periksa dahulu: 

docker ps -a --filter name=website-pertama
curl -I http://127.0.0.1:8080

Jika website berjalan, dari perangkat lain di jaringan lokal coba buka http://192.168.1.100:8080/. Ganti IP jika alamat STB berubah.

07

Website Laravel / CMS

WEB

CMS adalah aplikasi Laravel yang dijalankan melalui container bernama cms-laravel. Container pernah menggunakan image lokal cms-laravel:latest, perintah proses apache2-foreground, direktori kerja /var/www/html, dan port host 8081 menuju port container 80.

Folder proyek yang pernah disebut adalah /srv/data/CMS. Namun, container CMS pada pemeriksaan sebelumnya tidak memiliki mount. Artinya, file aplikasi yang ada di dalam container belum tentu sama atau tersinkron dengan folder proyek di host. Jangan menghapus atau mengganti container sebelum memastikan source code dan data penting sudah disalin serta dapat dibangun ulang.

Periksa CMS

docker ps --filter name=cms-laravel
docker logs --tail 100 cms-laravel
curl -I http://127.0.0.1:8081
docker inspect cms-laravel --format '{{json .Mounts}}'

Jika CMS tidak merespons, periksa log container, status database, konfigurasi environment, dan koneksi Docker network sebelum mengubah konfigurasi.

08

Database MariaDB

DATABASE

Container database yang pernah tercatat bernama mariadb-news, menggunakan MariaDB 11. Port host yang tercatat adalah 3307, diteruskan ke port container 3306. Data database pernah dipasang dari host di /mnt/mariadb-data/data.

Periksa status dan log

docker ps --filter name=mariadb-news
docker logs --tail 100 mariadb-news
docker inspect mariadb-news --format '{{json .Mounts}}'

Jangan menaruh password database di dokumentasi, screenshot, GitHub, atau pesan publik. Hindari mengekspos port database ke internet. Untuk penggunaan lokal, aplikasi di network Docker sebaiknya mengakses database melalui nama container/service dan port internal, sesuai konfigurasi yang benar.

Jangan menghapus folder database atau menjalankan perintah penghapusan volume sebelum membuat dan memeriksa backup. File database tidak selalu bisa dipulihkan hanya dengan membuat container baru.
09

Akses Internet melalui Cloudflare Tunnel

JARINGAN

Container cloudflare-cms pernah dijalankan pada network Docker cms-network dengan target http://cms-laravel:80. Bentuk perintah yang pernah digunakan: 

docker run -d \
  --name cloudflare-cms \
  --restart unless-stopped \
  --network cms-network \
  cloudflare/cloudflared:latest \
  tunnel --no-autoupdate --url http://cms-laravel:80

Perintah ini menggambarkan konfigurasi Quick Tunnel yang pernah dipakai. Jalankan hanya jika container belum ada; periksa terlebih dahulu dengan docker ps -a --filter name=cloudflare-cms.

Periksa URL dan log tunnel

docker ps --filter name=cloudflare-cms
docker logs --tail 100 cloudflare-cms

Jika memakai Quick Tunnel, URL biasanya berakhiran trycloudflare.com dan dapat berubah setelah tunnel dibuat ulang. URL lama tidak boleh dianggap masih aktif tanpa diuji.

Cloudflare Tunnel menghindari kebutuhan membuka port masuk router, tetapi tidak otomatis membuat aplikasi aman. Tetap periksa autentikasi aplikasi, konfigurasi database, rahasia environment, dan pembaruan sistem.

10

Pengecekan Website yang Sedang Running

OPS

Mulai dengan melihat container beserta port-nya:

docker ps --format "table {{.Names}}\t{{.Image}}\t{{.Status}}\t{{.Ports}}"

Kemudian uji website lokal dari STB:

curl -I http://127.0.0.1:8080
curl -I http://127.0.0.1:8081

Periksa juga port yang mendengarkan koneksi:

ss -tulpn

Status HTTP seperti 200, 301, atau 302 biasanya menunjukkan ada respons web. Status 4xx atau 5xx perlu ditelusuri; status tersebut tidak otomatis berarti container mati.

Dari laptop/HP yang berada di jaringan yang sama, coba alamat berikut:

  • Website statis: http://192.168.1.100:8080/
  • CMS Laravel: http://192.168.1.100:8081/

Alamat di atas berlaku jika container dan port masih sama serta firewall/jaringan mengizinkan koneksi.

11

Backup dan Ketahanan Data

BACKUP

Data penting yang perlu diperhatikan mencakup source code Laravel, file upload pengguna, konfigurasi yang tidak mengandung rahasia untuk dokumentasi, serta dump database.

  • Simpan backup di lokasi berbeda dari disk server jika memungkinkan.
  • Backup database menggunakan mekanisme dump yang sesuai dengan versi dan konfigurasi MariaDB.
  • Jangan menganggap image Docker sebagai backup data aplikasi.
  • Periksa apakah folder upload benar-benar di-mount ke host. Backup folder host tidak akan mencakup data yang hanya tersimpan di filesystem container.
  • Uji pemulihan backup secara berkala; file backup yang belum pernah diuji belum tentu dapat dipulihkan.

Backup storage CMS pernah disalin ke /srv/data/CMS-persistent/storage/. Itu tidak dengan sendirinya membuktikan semua data CMS atau database sudah memiliki backup lengkap.

12

Keamanan Dasar

SECURITY
  • Gunakan password yang kuat dan unik untuk akun server serta database.
  • Jangan publikasikan file .env, file backup environment, token Cloudflare, password, atau kunci aplikasi.
  • Pastikan file rahasia dikecualikan dari Git, termasuk file bernama .env.backup-* dan dump konfigurasi yang mengandung rahasia.
  • Perbarui Armbian, Docker image, dan dependency aplikasi secara terencana.
  • Jangan membuka port database ke internet.
  • Batasi layanan yang dipublikasikan; gunakan autentikasi untuk panel admin.
  • Periksa log dan siapkan backup sebelum melakukan perubahan besar.
  • Ingat bahwa perangkat yang mati listrik tidak dapat mengirim alert dari dalam perangkat itu sendiri. Monitoring saat server mati memerlukan pemantau eksternal atau perangkat lain.
Jika password database pernah tercatat atau dibagikan di tempat yang tidak aman, rencanakan rotasi password dengan memperbarui konfigurasi database dan aplikasi secara terkoordinasi. Jangan mengganti APP_KEY Laravel sembarangan karena data terenkripsi atau sesi yang ada bisa terdampak.
13

Kendala yang Pernah Ditemui

OPS
  • Perintah Docker sempat salah penulisan saat menjalankan Nginx; perintah yang benar menggunakan opsi -p 8080:80.
  • Nama perangkat dan alamat IP perlu dipastikan sebelum menjalankan perintah remote.
  • Cloudflare Tunnel pernah mengalami kendala akibat salah ketik pada opsi host gateway saat percobaan lain. Periksa log dan nama layanan dengan teliti jika tunnel gagal.
  • Container CMS pernah terdeteksi tanpa mount. Ini penting untuk dituntaskan sebelum container dibangun ulang.
  • Ruang penyimpanan eMMC sistem lebih kecil daripada microSD. Periksa df -h agar penggunaan Docker tidak memenuhi root filesystem.
14

Pekerjaan Berikutnya

ROADMAP
  1. Verifikasi status terbaru seluruh container, port, dan URL website.
  2. Pastikan source code CMS dan file upload dipasang sebagai volume/bind mount yang benar.
  3. Pastikan backup database serta file aplikasi dapat dipulihkan.
  4. Pastikan akses publik menggunakan URL yang benar dan HTTPS aktif.
  5. Rancang CI/CD dengan GitHub Actions setelah alur build, secret, backup, dan deployment aman.
  6. Evaluasi kebutuhan domain sendiri jika ingin URL yang tetap.
